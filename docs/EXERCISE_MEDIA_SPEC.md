# Exercise Media Specification

The contract every exercise animation must satisfy. Generated by the codex CLI, validated
by a script, rendered by the app.

---

## 1. Why SVG and not images or GIFs

The codex CLI on this machine is authenticated through a ChatGPT subscription. That grants
**code generation, not image-API access** — so "ask codex for a picture" is not something
this setup can do. Codex writes code, so the media is code.

That constraint turned out to be a better answer anyway:

|                                  | Animated SVG                  | Generated GIF           |
| -------------------------------- | ----------------------------- | ----------------------- |
| File size                        | ~5 KB                         | 200 KB - 2 MB           |
| Sharpness                        | Perfect at any size           | Fixed resolution        |
| Recolours with the palette       | **Yes**                       | No                      |
| Consistency across 25+ exercises | Enforced by a shared template | Hope                    |
| Reviewable in a pull request     | Yes, it is text               | No, it is a binary blob |
| Editable by hand afterwards      | Yes                           | Not really              |

The palette point is the one that matters most: because every colour in these files is a
CSS custom property, **changing the app's colour palette recolours every exercise animation
automatically**.

## 2. How consistency is actually achieved

Not by asking nicely. By three mechanisms:

1. **A written contract** — this document, passed into every generation call.
2. **A committed exemplar** — `public/exercise-media/_exemplar-seated-cable-row.svg`, a
   hand-checked reference passed into every generation call as the style to match.
3. **An automated validator** — `tools/exercise-media/validateExerciseSvg.mjs`, which
   rejects any output that breaks the contract. It runs in CI, so a bad file cannot merge.

## 3. The contract

Every generated file MUST:

| #   | Requirement                                                                                                                                                                                 |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Be a single self-contained `.svg` file. No external references of any kind                                                                                                                  |
| 2   | Use exactly `viewBox="0 0 400 400"` and carry no `width` or `height` attribute                                                                                                              |
| 3   | Take **every** colour from the approved CSS custom property list in section 4, each with a fallback: `fill="var(--muscle-body-fill, #1C1934)"`                                              |
| 4   | Contain no literal colour outside a `var()` fallback. No `#hex`, `rgb()`, or named colours anywhere else                                                                                    |
| 5   | Animate with CSS `@keyframes` inside a `<style>` element. No SMIL (`<animate>`), no JavaScript                                                                                              |
| 6   | Loop over exactly **3 seconds**, `animation-iteration-count: infinite`, returning to the start position                                                                                     |
| 7   | Wrap all animation in `@media (prefers-reduced-motion: no-preference)`, so the figure renders in its start position when motion is reduced                                                  |
| 8   | Use stroke width `3` for body outlines and `2` for equipment                                                                                                                                |
| 9   | Draw the figure in profile, facing right, occupying roughly 70% of the canvas height                                                                                                        |
| 10  | Highlight the primary target muscle with `--muscle-highlight-primary` and the secondary with `--muscle-highlight-secondary`, each at 0.85 opacity, pulsing gently in time with the movement |
| 11  | Include `<title>` and `<desc>` elements. The `<desc>` describes the movement for screen readers                                                                                             |
| 12  | Carry `role="img"` and `aria-labelledby` pointing at the `<title>`                                                                                                                          |
| 13  | Be under 12 KB                                                                                                                                                                              |
| 14  | Contain no comments, no editor metadata, no `<metadata>` block                                                                                                                              |

## 4. Approved CSS custom properties

**This list is exhaustive.** Any other custom property fails validation.

| Property                       | Fallback  | Use                                          |
| ------------------------------ | --------- | -------------------------------------------- |
| `--muscle-body-fill`           | `#1C1934` | Body and limb fill                           |
| `--muscle-body-stroke`         | `#4A4470` | Body outline, joints                         |
| `--muscle-highlight-primary`   | `#A855F7` | The primary target muscle                    |
| `--muscle-highlight-secondary` | `#3D8BFF` | Secondary / assisting muscles                |
| `--muscle-equipment-fill`      | `#241F42` | Machines, benches, dumbbells                 |
| `--muscle-equipment-stroke`    | `#5A5385` | Equipment outlines                           |
| `--muscle-motion-trail`        | `#7C5CFF` | The optional arc showing direction of travel |

## 5. File naming

`public/exercise-media/{exerciseId}.svg`, where `exerciseId` is the camelCase id from
`src/content/exercises/`.

```
public/exercise-media/seatedCableRow.svg
public/exercise-media/legPress.svg
public/exercise-media/dumbbellRomanianDeadlift.svg
```

The exemplar is prefixed with an underscore so it sorts first and is obviously not an
exercise: `_exemplar-seated-cable-row.svg`.

## 6. Generating a file

```bash
node tools/exercise-media/generateExerciseSvg.mjs seatedCableRow
```

The script:

1. Loads the exercise definition from `src/content/exercises/`.
2. Builds a prompt from **this document** + **the exemplar file** + a per-exercise brief
   (start position, end position, target muscles, equipment).
3. Runs `codex exec` with that prompt.
4. Writes the result to `public/exercise-media/{exerciseId}.svg`.
5. Runs the validator and **deletes the file if it fails**, so a broken asset never lands.

Generate everything the current programme needs:

```bash
node tools/exercise-media/generateExerciseSvg.mjs --all
```

## 7. Validating

```bash
node tools/exercise-media/validateExerciseSvg.mjs           # everything
node tools/exercise-media/validateExerciseSvg.mjs legPress  # one file
```

Checks, in order: file exists and parses as XML; `viewBox` is exactly right; no `width` or
`height`; every colour is an approved `var()`; no literal colours; no `<script>`, `<image>`,
`<use href="http...">` or any external reference; no SMIL elements; a `<style>` block exists
with a 3s keyframe animation; a reduced-motion media query is present; `<title>` and
`<desc>` exist; file is under 12 KB.

CI runs this on every push. A file that fails validation blocks the build.

## 8. Reviewing a generated animation

The validator checks the contract, not whether the animation is any good. Before committing,
open it and confirm:

- The movement is anatomically plausible and matches the actual exercise.
- It matches the exemplar's visual style — same proportions, same weight of line.
- The right muscles glow. Getting this wrong teaches bad information, which is worse than
  having no picture at all.
- It reads clearly at roughly 160 x 160 px, which is how big it is on a phone.
- It still looks right after switching the palette in Settings.

If it is wrong, re-run the generator — output varies between runs. If it is wrong twice,
fix the brief in the exercise definition rather than fighting the generator.

## 9. When codex is unavailable

The generator is a build-time tool, not a runtime dependency. The app renders committed SVG
files and does not know or care how they were produced. Hand-written SVG that passes the
validator is perfectly acceptable.

The `ExerciseAnimation` component falls back to a muscle-group icon when a file is missing,
so a missing asset degrades gracefully instead of breaking a session mid-workout.
